## NRE 排查：静态字段被重载清零 + 精确定位日志
- 现象：重载后多处 NullReferenceException（EntranceWindow.OnCreate 解释器代码、TMP_SubMeshUI.UpdateMaterial AOT），用户不知哪个变量为 null。
- **根因**：`RestoreReusedClasses` Pass 2（InterpreterImage.cpp）与 `RestoreCachedGenericClassesPass2`（GenericClass.cpp）**无条件把 `klass->static_fields = nullptr`** → 所有复用类/泛型实例的静态字段在重载后清零。非 cctor 赋值的静态状态（单例 `_instance`、运行时缓存）全部变 null → NRE。
- **修复（静态状态保留）**：静态布局不变时保留 `static_fields` 存储与 cctor 状态（`cctor_started`/`cctor_finished_or_no_cctor`），布局变化时维持原重置行为。
  - 非泛型：Pass 1 用 `oldStaticFieldsSizes` 数组先存旧 `static_fields_size` 再覆盖，Pass 2 比较旧==新则保留。
  - 泛型实例：比较实例的（旧）`static_fields_size` 与定义的（新）`static_fields_size`。
- **NRE 定位日志**：`Interpreter_Execute.cpp` 的 `catch (Il2CppExceptionWrapper)` 块中，NRE 时打印 `[ReloadDiag] NRE at <命名空间>.<类>::<方法> ipOffset=<转换后指令流偏移> token=0x... image=...`（frame->method + ip - ipBase）。AOT 代码（如 TMP）的 NRE 无此行号能力，但大概率同源于静态清零。

## 指令解码日志引入崩溃 + 加固（用户报告）
- **崩溃机制**：`CALL_INTERP_VOID` 是**同 Execute 实例内帧切换**（SAVE_CUR_FRAME + PREPARE_NEW_FRAME_FROM_INTERPRETER），宏内 `imi` 先于 `ip` 更新；若 NRE 在此窗口抛出（如被调方法 cctor 里 NRE），catch 中 **imi 属于新方法、ip 指向旧方法指令流** → 解码用错 `imi->resolveDatas` → 野指针解引用崩溃。另有传播帧 ip 为恢复值、非抛出指令的误导/风险。
- **加固**（catch 块解码前）：①`ipInCodes` 校验——`ip >= imi->codes && ip+16 <= imi->codes + imi->codeLength`（PDBImage.cpp 有同款校验先例；codeLength 为字节数）；②`static thread_local const Il2CppException* s_nreInstrDecodedEx` 去重——每个异常对象只在首次（抛出帧）解码一次。`InterpMethodInfo::resolveDatas` 无计数字段，无法索引边界检查，靠①②保证指令真实。
- 教训：**catch 块里的 frame/imi/ip/ipBase 局部变量在帧切换宏中间态可能互不匹配**；在 catch 里做任何依赖它们一致性的操作前必须校验。

## NRE 根因收敛（reload_diag(2).log + 用户 A/B 实验）
- **指令解码生效**：`EntranceWindow::OnCreate ipOffset=4032` 的 NRE = `CallInterp_ret`(op=315) 调用 `Loxodon...BindingBuilder\`2::For`，**接收者（BindingBuilder\`2 实例）为 null**。枚举值=行号-26（已用 CallCommonNativeInstance_i8_0=341 与崩溃栈互验）。
- **用户 A/B 结论**：重载前进过界面（类型初始化过）→ 重载后正常；没进过（类型未初始化）→ 重载后首次进入 NRE。用户猜想：复用过程对未初始化类型"错误标记已初始化"（MonoScript 缓存的类型）。
- **代码验证**：`Class::InitLocked` 做完整初始化（methods/fields/vtable/GC desc/RGCTX），Pass 3 对所有复用类调 Class::Init——"标记已初始化"本身有完整 setup 支撑。A/B 的真正差异：**初始化过的类 → 方法走复用（OnCreate 旧 interpData + 旧 resolveDatas → 同一批复用类对象，绑定链在"旧世界"自洽运行）；未初始化的类 → 重载后全部全新创建/Transform（"新世界"），新世界在某环节产生了 null builder**。
- 非泛型方法复用路径（Class.cpp SetupMethodsLocked）**不重置 interpData**（保留旧转换码+旧 resolveDatas）——对相同 DLL 恰好自洽，这是场景 A 能跑通的原因之一。
- **新增"回溯写入者"诊断**（Interpreter_Execute.cpp catch 块）：提取接收者槽位（ldfld obj@ip+4 / stfld obj@ip+2 / CallInterp*·CallCommonNativeInstance* argBase@ip+2），用 `g_instructionSizes`（843 项，上限 `(uint16_t)HiOpcodeEnum::MethodBaseGetCurrentMethod`=842 自维护）从 ipBase 正向扫描到故障 ip，打印最后 3 条 dst(+2)/ret(+4) 操作数命中该槽的指令（ipOffset+op+operandPos），离线按 op 语义甄别真正的写入者；call 类写入指令还会解析打印 callee（偏移与故障解码一致：CallInterp/CallInterpVirtual 的 void→+4、ret→+8；CallNativeInstance/CallVirtual/CallNativeStatic 的 void/ret→+8、ret_expand→+12）。

## callee 确认（reload_diag(4).log）：Bind 虚调用返回 null
- 槽 20 写入链：`3776 BindingBuilder\`2::OneWay`(CallInterp_ret) → `3792 LdlocVarVar` → **`3832 BindingSet\`2::Bind`(CallInterpVirtual_ret)** → 4032 `For`(null)。C# 形态：`bindingSet.Bind(x).For(expr)`，**`BindingSet\`2<EntranceWindow,EntranceWindowVM>::Bind` 虚调用返回了 null**（Bind 正常实现 `return new BindingBuilder<...>(...)` 不可能返 null；且 Bind 内部无 NRE——抛出帧在 OnCreate，说明 Bind 正常"完成"却返回 null）。
- 两种候选：①**vtable 错乱**——虚分发落到非 Bind 的方法（合用户"标记已初始化"猜想：泛型实例 vtable 重建用了陈旧/错位方法数据）；②**Bind 方法体错**——inflate 方法 token/image 不匹配导致 Transform 了别的方法体。
