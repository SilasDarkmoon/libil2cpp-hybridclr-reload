## NRE 排查：静态字段被重载清零 + 精确定位日志
- 现象：重载后多处 NullReferenceException（EntranceWindow.OnCreate 解释器代码、TMP_SubMeshUI.UpdateMaterial AOT），用户不知哪个变量为 null。
- **根因**：`RestoreReusedClasses` Pass 2（InterpreterImage.cpp）与 `RestoreCachedGenericClassesPass2`（GenericClass.cpp）**无条件把 `klass->static_fields = nullptr`** → 所有复用类/泛型实例的静态字段在重载后清零。非 cctor 赋值的静态状态（单例 `_instance`、运行时缓存）全部变 null → NRE。
- **修复（静态状态保留）**：静态布局不变时保留 `static_fields` 存储与 cctor 状态（`cctor_started`/`cctor_finished_or_no_cctor`），布局变化时维持原重置行为。
  - 非泛型：Pass 1 用 `oldStaticFieldsSizes` 数组先存旧 `static_fields_size` 再覆盖，Pass 2 比较旧==新则保留。
  - 泛型实例：比较实例的（旧）`static_fields_size` 与定义的（新）`static_fields_size`。
- **NRE 定位日志**：`Interpreter_Execute.cpp` 的 `catch (Il2CppExceptionWrapper)` 块中，NRE 时打印 `[ReloadDiag] NRE at <命名空间>.<类>::<方法> ipOffset=<转换后指令流偏移> token=0x... image=...`（frame->method + ip - ipBase）。AOT 代码（如 TMP）的 NRE 无此行号能力，但大概率同源于静态清零。

## 指令解码日志引入崩溃 + 加固（用户报告）
- **崩溃机制**：`CALL_INTERP_VOID` 是**同 Execute 实例内帧切换**（SAVE_CUR_FRAME + PREPARE_NEW_FRAME_FROM_INTERPRETER），宏内 `imi` 先于 `ip` 更新；若 NRE 在此窗口抛出（如被调方法 cctor 里 NRE），catch 中 **imi 属于新方法、ip 指向旧方法指令流** → 解码用错 `imi->resolveDatas` → 野指针解引用崩溃。另有传播帧 ip 为恢复值、非抛出指令的误导/风险。
- **加固**（catch 块解码前）：①`ipInCodes` 校验——`ip >= imi->codes && ip+16 <= imi->codes + imi->codeLength`（PDBImage.cpp 有同款校验先例；codeLength 为字节数）；②`static thread_local const Il2CppException* s_nreInstrDecodedEx` 去重——每个异常对象只在首次（抛出帧）解码一次。`InterpMethodInfo::resolveDatas` 无计数字段，无法索引边界检查，靠①②保证指令真实。
- 教训：**catch 块里的 frame/imi/ip/ipBase 局部变量在帧切换宏中间态可能互不匹配**；在 catch 里做任何依赖它们一致性的操作前必须校验。

## 解码仍崩溃（11795 行 callee->klass）+ 二次修复
- **崩溃栈**：catch$3 @ Interpreter_Execute.cpp:11795（`callee->klass` 解引用野指针），抛出指令 @ 5717 = `CallCommonNativeInstance_i8_0`（调返回 i8 的 AOT 实例方法，native 内部或 _self null 抛 NRE）。

- **重要观察**（reload_diag(1).log）：崩溃发生在处理 `PollingCheckAliveRes::DoClearAssetCache ipOffset=224` 的 NRE 时；该 NRE 在两份日志里都出现在**重载前**（本次甚至无 DiagEnabled 行）→ **大概率与重载无关的常态异常**（疑似调 Stopwatch.ElapsedMilliseconds/DateTime.Ticks 一类 i8 返回值的 AOT 实例方法时接收者为 null）。用户真正关心的 EntranceWindow::OnCreate NRE 还没跑到就被我的解码崩掉了。
- 教训：**解释器指令族内不同变体的操作数布局不统一，解码必须逐 opcode 验证，禁止按族猜测偏移**。
