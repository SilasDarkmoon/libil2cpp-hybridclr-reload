## 调研：Unity 引擎底层如何使用 il2cpp 类型（对照 Unity2019.1.14f1 源码）
- **结论**：引擎**不直接访问** Il2CppClass/Il2CppImage 字段——整个 Runtime/ 与 Modules/ **无任何文件 include `il2cpp-class-internals.h`**；只 include `il2cpp-api-types.h`（opaque typedef）+ `il2cpp-blob.h` + `il2cpp-api-functions.h`（~243 个 DO_API 条目，唯一契约）。
- **机制**：`il2cpp-api-functions.h` 是 X-macro；libil2cpp 侧 `il2cpp-api.h` 展开为 IL2CPP_EXPORT 声明（实现在 il2cpp-api.cpp→vm::）；Unity 侧 `Runtime/ScriptingBackend/Il2Cpp/ScriptingIncludes_Il2Cpp.h` 静态链接时展开为 extern 声明，`LOAD_IL2CPP_DYNAMICALLY` 时展开为**函数指针**，`Runtime/Scripting/Il2CppLoader.cpp::LoadIl2Cpp()` 用 LookupSymbol 按名解析。引擎大部分代码再隔一层后端无关 `scripting_*`（ScriptingApi.h / ScriptingApi_Il2Cpp.cpp 逐行转发）。
- **直接内存访问的 2 个例外**：①对象头硬编码 `SCRIPTING_OBJECT_HEADERSIZE=sizeof(void*)*2`（klass+monitor，读 m_CachedPtr，属 ABI 稳定布局）；②`g_Il2CppClassUserDataOffset = il2cpp_class_get_userdata_offset()`（= `offsetof(Il2CppClass, unity_user_data)`，运行时查询而非硬编码，GetComponent 优化在此偏移直读写 Unity::Type*）。
- **一致性保证**：opaque 隔离 + 单一源码源（Unity 树内 `External/il2cpp/il2cpp/libil2cpp` 就是 libil2cpp 源码，头文件共享）+ 运行时 offsetof。
- **对本项目启示**：vtable 布局改动/加字段对引擎透明；但 `unity_user_data` 字段必须保留，且不能破坏"对象头=2 指针"ABI。

## 方案评估：用户提议用 Adapter 模式替代指针复用（结论：不建议全量做）
- **用户想法**：改 il2cpp-api-functions.h 各 API 实现，返回给 Unity 的指针用 Adapter 包一层（shell→real），重载后只换 shell 内 real 指针，从而抛弃 Il2CppClass/MethodInfo 复用。
- **评估结论**：Adapter 只能覆盖"Unity 引擎边界"（4 个指针逃逸边界中的 1 个），覆盖不了：②托管堆反射对象（RuntimeType.value=裸 Il2CppType*、RuntimeMethodInfo.mhandle=裸 MethodInfo*，icall 读写+指针相等比较）、③每个对象头 obj->klass（GC/AOT/解释器直接解引用，复用方案存在的根本原因）、④内部缓存（s_GenericClassSet 按 typeHandle hash、AOT class_inst->type_argv 存 &klass->byval_arg）。
- **硬障碍**：Il2CppType 按值嵌入（&klass->byval_arg 地址即 Type*）；unity_user_data 偏移 Unity 直写；指针 == 相等性语义要求严格单射；243 API+icalls+回调+内存快照全边界包装，漏一处=隐蔽崩溃；热路径 real→shell 哈希查询开销。
- **推演悖论**：shell 要同时满足 &byval_arg 稳定 + userdata 偏移可写 + obj->klass 指向，就必须是完整布局真实的 Il2CppClass，重载后重指向其内部字段——收敛回现在的 Pass1-3，还多套一层 indirection。
- **建议的替代路线**：①最小 Adapter=只对 Image/Assembly 保指针稳定（即已实施的 image 复用修复）；②"换体不换头"（swap bodies）：新类完整构建后交换新旧内存内容，Pass1-3 收敛为"修复指向类体内部的自引用清单"（&byval_arg/element_class/type_argv 回指/vtable），可维护性最好；③现状工程化（修复点沉淀为显式不变式+重载后自检）。用户暂未表态，仅要求评估勿动手。
