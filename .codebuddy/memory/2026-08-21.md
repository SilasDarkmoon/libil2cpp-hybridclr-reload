## ★★ 根因锁定（reload_diag(3).log + Unity 源码）★★

- **根因**：`CanTransferTypeAsNestedObject`（EmitSerializationCommandsForField.cpp:18-38）第 4 项检查 `GetMonoManager().GetAssemblyIndexFromImage(fieldType->image) == -1` → 返回 false → `EmitSerializationCommandsForManagedObjectField`(58-59) **直接 return，不生成该嵌套 managed 对象字段（s_currVariable）的指令**。前 3 项（SERIALIZABLE 标志/非抽象/非 corlib）都通过。
- `GetAssemblyIndexFromImage`（MonoManager_Il2Cpp.cpp:197-207）**按指针**在 `m_ScriptImages[]` 里查 image；`m_ScriptImages` 由 `LoadAssemblies()`（117-140）**仅启动时**经 `il2cpp_domain_assembly_open` 填一次，**重载后不更新**。**HybridCLR 重载产生新 Il2CppImage（新指针），不在 `m_ScriptImages` → 查找返回 -1**。
- **不对称解释**：①子 UIVA 正常=指令**重载前**构建（旧 image 已注册→通过），随复用类同指针存活；②EW 失败=指令**重载后**首次构建（新 image→-1→s_currVariable 被剔除）；③场景 A 正常=重载前进界面，EW 指令重载前构建；④预热有效=重载前构建 EW 指令。
- **Player 反序列化流程**（SerializableManagedRefTransfer.h:31-43 `TransferEngineAndMonoInstance`）：引擎数据（m_Script→SetScript→RebuildMonoInstance 建实例）与托管字段传输是**两次独立 Transfer**；实例存在才 `TransferScriptingObject`，否则**静默跳过**。
- **已加 ImageRegCheck 探针**（class_get_flags 挂钩）：对 VariableArray 对比 `klass->image` vs `il2cpp_assembly_get_image(il2cpp_domain_assembly_open(domain,"Loxodon.Framework.dll"))`，打 MATCH=0/1。下一跑确认 MATCH=0（不一致）即实锤。
- **修复方向（待与用户讨论）**：让重载后的 image 指针与 MonoManager 注册的一致——①HybridCLR 重载时**复用 Il2CppImage 指针**（像复用 Il2CppClass）；或 ②找到热更程序集向 MonoManager 注册的入口，重载后更新 `m_ScriptImages`（但 MonoManager 是 Unity 代码，需从 libil2cpp 侧想办法）。

- **首载（170-177）**：`ass=placeHolderAss; image2=ass->image`——**复用占位程序集的 Il2CppImage**（=MonoManager 启动时 `LoadAssemblies` 经 `il2cpp_domain_assembly_open` 注册进 `m_ScriptImages` 的那个 image）。
