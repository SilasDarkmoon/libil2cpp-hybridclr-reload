# 2026-07-29 工作日志

## 问题：AOT generic method not instantiated in aot (ProxyPropertyInfo`2[Transform,Vector3]::.ctor)

### 用户补充的关键背景
- `AOTHomologousImage` 是 AOT 补充元数据，不可热更，第二遍加载报错被忽略
- `IsInterpreter` 对应两种情况：热更程序集 + AOT 补充元数据
- 项目使用完全泛型实例共享（AOT 生成通用实现）
- `IsImplementedByInterpreter` 只检查 `AOTHomologousImage::FindImageByAssembly`，不覆盖解释器程序集

### 分析
问题有两个层面：
1. **`s_GenericMethodMap` 缓存陈旧 token**：缓存了 reload 前的 inflated `MethodInfo`，其 `token` 来自旧 image。`GenericClass::SetupMethods` 调用 `Inflate` 时可能命中旧缓存 → `GetMethodBody(newImage, oldToken)` → OOB
2. **泛型复用路径 `methodPointerCallByInterp` 置空**：复用路径将 `methodPointerCallByInterp = nullptr` + `initInterpCallMethodPointer = false`，强制走 `InitAndGetInterpreterDirectlyCallMethodPointerSlow`。但 `IsImplementedByInterpreter` 对解释器程序集返回 false → 重新初始化失败 → `methodPointerCallByInterp` 保持 null → `RaiseAOTGenericMethodNotInstantiatedException`

### 修复
1. `RestoreReusedClasses()` 开头调用 `GenericMethod::ClearStatics()` 清除 `s_GenericMethodMap`
2. 泛型复用路径从 inflated method 继承 `methodPointerCallByInterp`/`virtualMethodPointerCallByInterp`/`initInterpCallMethodPointer`，而非置空
3. `interpData` 仍置空以强制重新 Transform

### 诊断日志
1. `GetMethodBody` OOB 日志增加 `imageName` 字段
2. `HiTransform::Transform` 在 methodBody 为 null 时打印 klass/method/token/image/isInterpType/isInterpImpl/is_inflated/is_generic
3. `GenericClass::SetupMethods` 在 `inflated->token != methodDefinition->token` 时打印 TokenMismatch 日志（复用和非复用路径都有）

### 修改的文件
- `hybridclr/metadata/InterpreterImage.h` — GetMethodBody OOB 日志增加 imageName
- `hybridclr/metadata/InterpreterImage.cpp` — 添加 GenericMethod.h include，RestoreReusedClasses 开头调用 ClearStatics
- `hybridclr/transform/Transform.cpp` — methodBody null 时打印详细诊断
- `vm/GenericClass.cpp` — TokenMismatch 诊断日志 + 复用路径从 inflated 继承 methodPointerCallByInterp + SetupMethods 调用日志 + ShouldRestoreGenericClass=false 日志
- `metadata/GenericMethod.cpp` — ClearStatics 调用日志 + 添加 os/Directory.h 和 os/Environment.h include

## 问题：InvalidCastException: EnumEqualityComparer→EqualityComparer (log 11)

### 根因
- Pass 2 重置了 `typeHierarchy = nullptr` 和 `typeHierarchyDepth = 0`
- `IsInst`（类型转换检查）直接读 `typeHierarchy` 和 `typeHierarchyDepth`，**不会触发 Class::Init 或 Class::SetupTypeHierarchy**
- NonGeneric Pass 3 的 cctor 访问了已被 Generic Pass 2 重置但尚未被 Generic Pass 3 重建的泛型实例类
- `typeHierarchyDepth == 0` → `IsInst` 循环不执行 → 转换失败 → `InvalidCastException`

### 修复
- Pass 2（非泛型和泛型）重置 `typeHierarchy = nullptr` 和 `typeHierarchyDepth = 0`
- Pass 3 通过 `Class::Init` 重建继承树（`InitLocked` → `SetupTypeHierarchyLocked`）
- `IsInst` → `IsAssignableFrom` → `Class::Init` 也会触发重建
- **泛型 Pass 3 重新解析 parent**：从 generic type definition 的 parent inflate，调用 `Class::FromIl2CppType`
- **Pass 1 后 rehash 三个缓存**：`s_GenericInstSet`、`GenericMetadata::s_GenericClassSet`、`GenericClass::s_GenericClassSet`
  - 原因：Pass 1 更新 `byval_arg.data.typeHandle`，而 `Il2CppTypeHash::Hash` 对 CLASS/VALUETYPE 用 `typeHandle` 指针值做 hash。旧条目 hash 失效，新 lookup hash 不同 → 找不到旧条目 → 创建新类 → `ParentMismatch` → `InvalidCastException`
  - 修复：Pass 1 后清除并重新插入所有条目，用新 `typeHandle` 重新计算 hash

## 问题：klass->image 被错误地设为 newImage (log 12)

### 根因
`ShouldRestoreGenericClass` 不仅检查泛型定义，还递归检查泛型参数。如果泛型参数来自正在 reload 的 DLL，函数返回 true。但 Pass 1 的代码 `klass->image = newImage` 把 `klass->image` 设成了当前 reload 的 DLL 的 image，而不是泛型定义所在的 image。

例如 `ProxyPropertyInfo`2[SomeTypeFromRuntimeScripts, Vector3]`：
- 泛型定义在 `Loxodon.Framework.dll`
- 泛型参数 `SomeTypeFromRuntimeScripts` 来自 `RuntimeScripts.dll`
- reload `RuntimeScripts.dll` 时 `ShouldRestoreGenericClass` 返回 true（因为泛型参数）
- `klass->image` 被错误地设为 `RuntimeScripts.dll` 的 image
- 后续 `GetMethodBody` 在 `RuntimeScripts.dll` 的 image 上用 `Loxodon.Framework.dll` 的 token 查找 → OOB

### 修复
Pass 1 中，当 `defIsInterp` 为 true 时，把 `klass->image` 设为泛型定义类的 `image`（`defKlass->image`），而非 `newImage`。
