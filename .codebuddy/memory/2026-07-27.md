# 2026-07-27

## BadImageFormatException 根因与修复
- **根因**：`GetUnderlyingInterpreterImage(methodInfo)` 通过 `klass->image` 获取 image。重载后 `klass->image` 被更新为新 image，但旧 `MethodInfo`（被 delegate/vtable 引用）的 `token` 和 `methodMetadataHandle` 仍然是旧 image 的。`GetMethodBody` 在新 image 上用旧 token 查找 → token 不匹配 → `ReadMethodBody` 解析到错误的方法头 → `localVarSigToken` 不正确 → `GetBlobReaderByRawIndex` 返回 `length=0` → `ReadType` 读到 `etype=0` → `BadImageFormatException`。
- **修复**：在 `SetupMethodsLocked`（非泛型类）和 `GenericClass::SetupMethods`（泛型实例类）中，通过方法签名匹配复用旧 `MethodInfo`，更新其 `token`/`methodMetadataHandle`/`methodPointer` 等指向新 image，清除 `interpData` 强制重新 transform。
- **关键点**：`HasReuseData()` 需要检查 `_reuseMethodMap`（不只 `_reuseClassMap`），因为 Pass 1 清空了 `_reuseClassMap` 但 `_reuseMethodMap` 保留。
- **泛型实例类特殊处理**：复用旧 inflated `MethodInfo` 时，需要先通过 `GenericMetadata::Inflate` 获取新的 inflated 数据，然后从 inflated `MethodInfo` 复制字段到旧 `MethodInfo`（不能直接从 `methodDefinition` 复制未 inflate 的值）。

## MissingMethodException 根因与修复
- **根因**：`GetMethodInfoFromMethodDef` 通过指针比较 `cur->methodMetadataHandle == methodDef`。重载后 `methodDef` 来自旧 image（因为 `ReadMethodInfoFromToken` 在旧 image 上调用——transform 缓存导致），而 `klass->methods` 中的 `methodMetadataHandle` 来自新 image。指针不匹配。
- **修复**：清除旧 `MethodInfo` 的 `interpData`，强制重新 transform。重新 transform 时 `GetUnderlyingInterpreterImage` 返回新 image，`GetMethodBody` 在新 image 上用新 token 查找。但需要确保旧 `MethodInfo` 的 `token` 也被更新为新 image 的 token（通过方法签名匹配复用）。
