# 2026-08-24 工作日志

## Adapter 实验选型：Il2CppImage 为最佳入手点（用户已重置代码库为全新状态）
- **背景**：用户决定实验将 il2cpp-api-functions.h 的指针改 Adapter 模式，要求选用途单一的指针入手（排除 Il2CppClass——用途多且被 Il2CppType 引用）。
- **选型结论：Il2CppImage**。理由：
  1. API 触点最少之一：11 个（出 5：get_corlib/assembly_get_image/class_get_image + image_get_entry_point 无关；入 6：class_from_name/exception_from_name_msg/image_get_assembly/get_name/get_filename/get_class_count/get_class）；
  2. 独立分配对象，无 byval_arg 式按值嵌入；
  3. Unity 侧用法单一：MonoManager m_ScriptImages 启动缓存 + GetAssemblyIndexFromImage 指针比较 + IsSystemCollectionsGenericList 的 `class_get_image(klass)==get_corlib()` 比较——稳定 adapter 天然满足；
  4. 对重载有真实价值：正是 08-21 实锤的 m_ScriptImages 根因所在，实验成了可直接替代 image 复用；
  5. 风险完全可控：内部 klass->image/ass->image 保持真实指针不动。
- **已知欠账（实验后期处理）**：Il2CppReflectionModule（System.Reflection.RuntimeModule）在托管堆内持有裸 const Il2CppImage*（il2cpp-object-internals.h:260-270），不经 API 边界；Adapter 管不到，需 image 复用或接受该路径不一致。
- **次选**：Il2CppAssembly（4 个 API，但被 Il2CppReflectionAssembly 托管持有）；Il2CppDomain（4 个 API 最简单，但重载不换 domain，实验无实际收益）。
- **实验落地建议**：通用模板 AdapterMap<real,adapter>（find-or-create + swap 接口，反正 image 实验成功后会推广到 Assembly/FieldInfo）；包裹点清单=上述 11 个 API 在 il2cpp-api.cpp 的实现；验证点：GetComponent/IsSystemCollectionsGenericList 的 image 比较、monoManager class_from_name 路径。
- **Unity 侧对应文件路径**（用户问）：`D:\MyFiles\Downloads\Unity2019.1.14f1\External\il2cpp\il2cpp\libil2cpp\il2cpp-api-functions.h`（Unity 树内嵌 libil2cpp 源码，与工作区文件同源）；引用处=Runtime\ScriptingBackend\Il2Cpp\ScriptingIncludes_Il2Cpp.h:33 + Runtime\Scripting\Il2CppLoader.cpp:37-110。启示：adapter 包在实现层、DO_API 签名不变则 Unity 侧零改动。
