## FieldInfo Adapter 实施完成（同日，lint 全净，待构建验证）
- Assembly adapter 已由用户确认编译运行正常后开始 FieldInfo。
- **触点**：il2cpp-api 15 个（出 2：class_get_fields/class_get_field_from_name；入 13：12 个 field_* + custom_attrs_from_field）+ mono-api 8 处（6 直调 vm::Field::* + 2 直解引用）。
- **改动**：①api-types.h 加 FieldInfoAdapter typedef ②adapters.h 加 `FieldInfoAdapter{FieldInfo* real;}`（**非 const**——field API 签名多为 FieldInfo*，UnwrapField 返回可变指针，内部 const_cast）+ WrapField/UnwrapField/RemapFieldReal ③api-functions.h 15 签名 ④api.cpp 15 处，**修复 2 处内部直解引用**：:698 field_is_literal 的 field->type->attrs、:1457 custom_attrs_from_field 的 field->parent->image/field->token（先 unwrap 再访问）⑤mono-api 8 处，**修复 2 处直解引用**：:1776 mono_vtype_get_field_addr 的 ->offset、:1833 mono_custom_attrs_from_field_checked 的 ->token ⑥lint 0 诊断。
- **关键判断——iter cookie 不 adapter 化**：Class::GetFields 的 void** iter 内部存裸 FieldInfo*（fields 数组当前位置），但它是短期迭代状态（Unity 原样传回不长期缓存，单次遍历期间类不重建），与"长期身份指针"（序列化指令缓存的 FieldInfo）本质不同，无需处理。
- **FieldInfo 特有难点（热重载接入时）**：FieldInfo 嵌入 klass->fields 数组按值分配，地址稳定性依赖类；RemapFieldReal(oldField,newField) 的新旧配对须由重载流程按 (parent 类, 字段名) 完成——与 image/assembly 的"整对象配对"不同。且新类 fields 数组可能复用旧地址（分配器复用），hash key 冲突隐患需在接入时验证。
- **欠账**：field_get_type 返回真实 const Il2CppType*、field_get_parent 返回真实 Il2CppClass*（两者未 adapter 化，待后续阶段）。
- **编译错误修复（用户首次构建报 C2440）**：模板 AdapterMap 约定 real 成员为 const RealT*，FieldInfoAdapter::real 原为非 const FieldInfo* → RemapReal 里 adapter->real=newReal 编译失败。修复=FieldInfoAdapter::real 改 const FieldInfo*，UnwrapField 内 const_cast 交出可变指针。**教训：新 adapter 结构体的 real 成员必须统一 const RealT*，可变需求在 Unwrap 出口处理**。
