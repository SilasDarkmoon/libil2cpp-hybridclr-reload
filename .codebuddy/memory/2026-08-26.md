## 热重载方案分享 PPT 制作完成
- 产出：`.codebuddy/ppt/热重载方案分享.pptx`（18 页，16:9 宽屏，pptxgenjs 生成，源码 `make_ppt.js`）。
- 结构：封面 → 前期探索 3 页（用户口述补充，memory 中无记录）→ 为什么必须复用指针 → 架构总览（采集/三 Pass/方法与泛型复用）→ vtable 混合布局 → 踩坑时间线 → 坑 1~4（token 错配 / 泛型缓存 hash / Delegate 身份分裂 / 序列化 NRE 三连页：现象+排除法、诊断设施、根因链、修复）→ Adapter 方案权衡 → 经验总结 → 结尾。
- **前期探索 3 页（用户口述，值得长期记住的史实）**：
  1. 尝试 .NET AssemblyLoadContext（ALC）：.NET Core 3.0+ 程序集隔离加载/可卸载机制，但 Il2Cpp 是 AOT 裸 C++ 运行时无此设施，此路不通。
  2. 尝试反复加载同一 Assembly：被 PlaceHolder 的 token!=0 标志位拒绝（"reloading placeholder assembly is not supported!"）；修复后强行加载，纯 C# 逻辑可跑。
  3. 但 MonoBehaviour/ScriptableObject 全 Missing → 发现 Unity 底层按指针缓存（这正是 PlaceHolder Assembly 的设计用途），缓存清不掉 → 收敛到指针复用路线。
- 工具链：pptxgenjs（npm 全局）；QA 用 python-pptx 做几何越界检查（verify.py）+ 文本溢出估算（overflow_check.py）；视觉渲染用 PowerPoint COM 导出 PNG（export_png.ps1，中文路径需先复制为英文名，无 BOM ps1 里中文路径会乱码）。
- 修复过的布局问题：pitSlide 行高 0.42→0.38（坑 2 页溢出画布）、时间线第三列宽 7.6→6.9、封面标题 34pt→30pt（换行溢出）。
- **追加页（用户口述，值得长期记住的设计思路）**：「热重载友好架构」——固定的通用 MonoBehaviour/ScriptableObject 壳类型放非热更程序集承担全部序列化（Unity 缓存指针永远稳定），逻辑经标准 Assembly.GetType 转发到热更程序集纯逻辑类（类似通用 LuaBehaviour 模式）。这样无需复用 Il2CppClass，直接用探索二的二次加载即可；改写量少、利于 Unity 版本升级。代价：壳类型字段需与热更侧同步、每跳转发开销、存量项目迁移成本高。PPT 最终 19 页。
