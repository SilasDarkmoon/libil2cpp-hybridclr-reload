## Il2CppClass vtable 改为「固定布局 + 超阈值变量布局」混合方案
- 需求：`IL2CPP_MAX_VTABLE_SLOT_COUNT` 改回 128；新增 `IL2CPP_PRESERVED_VTABLE_SLOT_COUNT = 16`；当 `vtable_count + 16 > 128`（即 vtable_count > 112）时走**原变长 struct**逻辑，分配槽数 = `vtable_count + 16`，不再丢弃/截断；给 Il2CppClass 增加 `vtable_allocated_count` 字段记录实际分配的 vtable 槽数。
- 布局规则：`vtable[IL2CPP_MAX_VTABLE_SLOT_COUNT]` 仍为内联固定 128 槽（结构体末尾）。固定布局：分配 `sizeof(Il2CppClass)`，`vtable_allocated_count = 128`，`vtable_count` 不截断。变量布局：分配 `sizeof(Il2CppClass) + (vtable_count + 16 - 128) * sizeof(VirtualInvokeData)`，`vtable_allocated_count = vtable_count + 16`。
- 实现：`ClampVTableSlotCount` 重命名为 `Class::ComputeVTableAllocatedSlotCount(uint32_t vtableCount, namespaze, name)`，返回分配槽数；变量布局时仍向控制台 + `vtable_overflow.log`（UNITY_TEMPORARY_CACHE_PATH 或 `log/`）写 "vtable variable-layout" 日志。
- 分配点（均需先算 vtableAllocated 再分配，并设 `vtable_count` 与 `vtable_allocated_count`）：`vm/GlobalMetadata.cpp` FromTypeDefinition、`vm/GenericClass.cpp` CreateClass（用 `definition->vtable_count`，泛型实例后续 SetupVTable 仅同步 vtable_count 不再 clamp）、`metadata/ArrayMetadata.cpp` 数组类（用 slots）。另：`vm/Class.cpp` 泛型参数类(:283) 与指针类(:1921) 这两个特殊分配补设 `vtable_count=0; vtable_allocated_count=128`（calloc 会清零，必须显式赋值否则守卫误判）。
- `ArrayMetadata.cpp` `PopulateArrayGenericMethods` 原先 `if (vtableIndex >= IL2CPP_MAX_VTABLE_SLOT_COUNT) continue;` 改为 `if (vtableIndex >= klass->vtable_allocated_count) continue;`。
- 说明：所有 vtable 写/读都按 `vtable_count` 或 `vtable_allocated_count` 边界，变量布局下 `vtable_count+16` 覆盖了数组 interfaceOffset 越界槽（这正是 PRESERVED=16 的用途）。lint 全部通过。

## dev-reload：Il2CppClass 复用判定（设计结论）
- 是否复用某 Il2CppClass 的唯一判据：**该类型有存活实例且其 `obj->klass` 在 reload 后必须仍有效、且需被引擎重新链接**。il2cpp 对象的真实类型/vtable/字段布局/GC 布局/方法派发全由 `Il2CppObject.klass` 决定。
- **Q1 复用范围**：只有 PlaceHolderAssembly 中被重定义的 **UnityEngine.Object 派生类**需要复用（native-backed，跨 reload 存活）。纯托管类实例 reload 后被视为丢弃，旧 class 不复用只是跑旧代码、不崩溃（旧 class 不释放即可）。基类（Component/Behaviour/Object）在 UnityEngine.dll，不在占位集，天然稳定，无需复用。
- **Q2 数组/泛型**：不需单独复用逻辑。数组类按 `(elementClass, rank)` 缓存（`Class::GetArrayClass`→`ArrayMetadata::GetBoundedArrayClass`），泛型实例按 `(generic定义类, type args)` 缓存（`GetInflatedGenericInstanceClass`→`GenericClass::GetClass`）；只要被复用的 UnityEngine.Object 类**保持同一指针**，依赖它的数组/泛型类自动一致。**前提：必须"原地复用"（同指针、字段布局/vtable 槽数兼容），否则破坏缓存 key。** 例外：泛型*定义类*本身在占位集内被重定义时，已存活的 inflated 实例指向旧定义类 → 需单独评估。
- **Q3 MethodInfo**：不跨 reload 复用旧实例。复用 class 时**原地替换** `klass->methods[i]` 指向新程序集的 MethodInfo（新 method body/元数据），旧 MethodInfo 不再被引用（delegate 等）后可释放。托管 `System.Reflection.MethodInfo` / Delegate 在 domain reload 下不存活、也不能安全复用（method token 跨构建不同），让其失效即可；存活 MonoBehaviour 持有的旧 delegate 继续跑旧方法属可接受行为。

## dev-reload：Unity 2019.1.14f1 Native 层 Il2CppClass/MethodInfo 缓存点调查（源码 D:\MyFiles\Downloads\Unity2019.1.14f1）
- 引擎类缓存（与热更无关）：`ScriptingManager::m_TypeIndexToMonoClass`/`m_ScriptingClassToNativeType`（native Type↔UnityEngine wrapper 类映射，仅引擎程序集类）；`CommonScriptingClasses` + 构建期生成的 `CoreScriptingClasses.h`（源码包无此文件）+ 各模块 `SetupModuleScriptingClasses` 注册的类/方法。
- 用户程序集相关的 native 长期缓存点：
  1. `MonoScriptCache`（Runtime/Mono/MonoScriptCache.h）：用户脚本 `klass` + `methods[]`（全部魔法方法 MethodInfo*），引用计数，被 MonoScript 和每个 MonoBehaviour 持有，跨热重载存活。
  2. `MonoScriptCache::cachedSerializationData` → `SerializationCache::Data`：序列化命令缓存，含 FieldInfo*、字段类型 Il2CppClass*、数组/List 元素类（`LinearCollectionField::m_ElementClass`）、普通 [Serializable] 类（GeneralMonoObject）、[SerializeReference]（ManagedObjectReference）。**只在 domain reload 时清空**，热重载不触发——最大的坑。
  3. `Coroutine`（Runtime/Mono/Coroutine.h）：枚举器类 MoveNext/get_Current 的 MethodInfo* + 枚举器实例 GCHandle。
  4. `JobReflectionData`（Runtime/Jobs/JobReflectionData.h）：用户 Job struct 的 `userJobClass`、委托 Invoke MethodInfo*、委托 GCHandle，进程级不清。
  5. `PlayerLoopSystemInternal::type`：自定义 PlayerLoop 用户 struct 类。
  6. `Object::m_MonoReference`（BaseObject.h，GCHandle）：每个 native Object 缓存托管 wrapper 实例，实例头 `obj->klass` 指向 Il2CppClass。
- 结论修正（相对之前"仅 Object 派生类"的结论）：Object 派生类是核心，但**非 Object 派生**的以下类型也被 native 持有：序列化涉及的 [Serializable]/[SerializeReference] 类、Job struct、自定义 PlayerLoop struct、跨重载协程枚举器类、委托类。判定标准 = "是否有旧 Il2CppClass*/MethodInfo*/FieldInfo* 被 native 缓存或存活实例持有"。
- 数组/泛型：native 缓存的 T[]/List<T> 类主要在 SerializationCache；只要元素类 Il2CppClass 指针复用且不清 il2cpp 数组/泛型实例缓存，T[]/List<T> 天然同指针；但旧数组/泛型类内部 MethodInfo/methodPointer 需随重载修补。
- MethodInfo：需保持指针有效——`MonoScriptCache::methods`、Coroutine、JobReflectionData、序列化命令均长期持有 MethodInfo*；推荐 MethodInfo 结构体地址不变、原地更新 methodPointer/invoker_method 等字段（player 上无 MonoScriptCache 重建时机，运行中协程无法重建）。FieldInfo* 同理被序列化缓存持有。

## 实现 Il2CppClass / MethodInfo 跨 Assembly 重载复用
- 需求：Assembly 二次加载后，复用旧 Il2CppClass* 和 MethodInfo* 指针（保持地址不变），原地更新字段指向新元数据。
- 改动文件：
  1. **InterpreterImage.h**：新增 `_reuseClassMap`（fullName→Il2CppClass*）、`_reuseMethodMap`（sigKey→MethodInfo*）、`_oldImageForReuse`；公开方法 `CollectReusableObjects`、`RestoreReusedClasses`、`FindReusableClass/Method`、`TryReuseMethodFromMetadata`、`BuildClassFullName`、`BuildMethodSignatureKey`、`TypeToSigString`。
  2. **InterpreterImage.cpp**：
     - `TypeToSigString`：不触发类加载的类型→签名串（primitive 用枚举名，class/valuetype 直接读 TypeDef nameIndex/namespaceIndex，genericinst 递归，SZARRAY/ARRAY/PTR/BYREF 递归加后缀，VAR/MVAR 读 param->name）。
     - `BuildClassFullName`：递归 declaringType 构建 "Ns.Outer+Inner"。
     - `BuildMethodSignatureKey`：`"ClassFullName:MethodName(ParamType1,...)->ReturnType"`。
     - `CollectReusableObjects(oldImage)`：遍历旧 `_classList`，按 fullName 存入 `_reuseClassMap`；遍历旧 `klass->methods`，按 sigKey 存入 `_reuseMethodMap`；记录 `_oldImageForReuse`。
     - `RestoreReusedClasses()`：遍历新 `_typesDefines`，对每个类型构建 fullName（含嵌套类型递归），查 `_reuseClassMap`；命中则做 vtable 兼容检查 → 更新 image/typeMetadataHandle/byval_arg/counts/flags/bitfield → 置空 methods/fields/properties/events/nestedTypes/implementedInterfaces/interfaceOffsets/static_fields/rgctx_data/typeHierarchy → 重置 init flags → 存入 `_classList[i]`。最后调 `GenericClass::RestoreCachedGenericClasses` 处理泛型实例。
     - vtable 兼容：new vtable_count ≤ vtable_allocated_count → 正常复用；超出 → MSVC 上试 `_expand()` 原地扩容，其他平台直接放弃复用并写 `vtable_overflow.log` + stderr。
  3. **Assembly.cpp**：`Create()` 中在 `InitRuntimeMetadatas()` 前调 `CollectReusableObjects`，之后调 `RestoreReusedClasses()`。
  4. **Class.cpp**：`SetupMethodsLocked` 非 generic/array 分支新增复用逻辑——若 class 来自 InterpreterImage 且有 reuse map，对每个 method 调 `TryReuseMethodFromMetadata` 查签名匹配；命中则原地更新旧 MethodInfo 字段（methodPointer/parameters/return_type/token/handle 等），`klass->methods[index]` 指向旧 MethodInfo，跳过新建。未命中走原 MetadataCalloc 新建路径。
