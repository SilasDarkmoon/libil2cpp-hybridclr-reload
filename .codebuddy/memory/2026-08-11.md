## JsonUtility.ToJson 预热生效 + Unity 序列化缓存源码分析（Unity2019.1.14f1）
- **用户确认 JsonUtility.ToJson 预热暂时解决问题**。有效原因：预热在**重载前**（新鲜类）建好缓存，重载后复用**同一 klass 指针**（缓存键）→ 命中旧（好）缓存。
- **两层序列化缓存**（均在 Unity native，**均在 domainUnloadComplete 时 Reset**，我们的热重载不是域重载→**永不清空**）：
  1. **TypeTreeCache**（Runtime/Serialize/TypeTreeCache.cpp）：`s_Cache` 存 TypeTree（字段布局树，名/类型/偏移/大小/子节点）。键=hash(flags+PersistentTypeID+assembly-qualified 类名)。懒构建（首次 GetTypeTree），`Reset()` 清。
  2. **SerializationCache**（Runtime/Mono/SerializationBackend_DirectMemoryAccess/SerializationCache.cpp）：`s_Cache` 存 `SerializationCache::Data`（每字段的读/写序列化**指令**，按 binary/typetree/pptr/yaml 等 transfer 类型）。键=`klass.Hash()`（`scripting_class_get_hash`，类指针/名字）。懒构建（首次 FetchData），`Reset()` 清。经 `MonoScriptCache::cachedSerializationData` 被 MonoBehaviour 反序列化用（TransferScriptingObjectImpl.h:94 `FetchData(klass)`）。
  3. **MonoScriptCache**：每类方法缓存 + 指向 SerializationCache::Data 的指针。
- **构建路径**：`BuildSerializationCacheFor(klass)` → `BuildSerializationCommandQueueFor` → `EmitSerializationCommandsForField` → 用 `scripting_class_from_type`/`scripting_field_get_type` 解析字段类型。**根因假说**：复用类 field->type 的 typeHandle 陈旧（旧 image）→ `scripting_class_from_type` 解析失败/得陈旧类 → 序列化指令错 → 字段不填。场景 A 缓存建于重载前（新鲜类，typeHandle 正确）→ 正常。
- **重置（Q4）**：两缓存的 `Reset()` 都是内部静态函数，挂 `GlobalCallbacks::domainUnloadComplete`，**无公开 API**；触发需域重载（正是要避免的）或调 Unity 内部符号（未导出）。
- 待办：确认复用类 field->type->data.typeHandle 是否陈旧（DeserProbe 只打了指针值没解析验证）；找公开/可行的缓存重置或单条失效途径。
