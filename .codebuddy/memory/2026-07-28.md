# 2026-07-28

## 崩溃修复：ShouldRestoreGenericClass 未识别已复用的泛型定义类

### 崩溃现象
- 崩溃在 `Image::ReadType` 第 300 行（`IL2CPP_TYPE_VAR` 分支），调用 `GetGenericParameterFromIndex`
- 调用链：`GetInterpMethodInfo` → `HiTransform::Transform` → `MethodBodyCache::GetMethodBody` → `InterpreterImage::GetMethodBody` → `ReadMethodBody` → `ReadType`
- 发生在第一个 DLL 重载后、执行该 DLL 代码时

### 根因
1. `RestoreReusedClasses()` 更新了泛型定义类（如 `Dictionary<TKey,TValue>`）的 `klass->image` 指向新 image，并重新初始化了 methods（token 来自新 image）
2. 但 `gclass->type->data.typeHandle` 仍指向旧 image 的 `Il2CppTypeDefinition`（未被更新）
3. `ShouldRestoreGenericClass` 用 `gclass->type->data.typeHandle` 判断泛型实例类是否依赖被重载的 image → 返回 false
4. 泛型实例类的 `klass->image` 未被更新，仍指向旧 image
5. 但 method token 来自新 image（因为泛型定义类的方法已被重新初始化）
6. `GetUnderlyingInterpreterImage` 返回旧 image，`GetMethodBody(token)` 在旧 image 上用新 image 的 token 查找 → row index 不匹配 → 读到错误方法体 → 崩溃

### 修复
- 文件：`vm/GenericClass.cpp`
- `ShouldRestoreGenericClass` 增加参数 `Il2CppClass* cachedClass`（快速路径检查 `cachedClass->image == newImage`）
- 当 `typeDef` 来自旧 image 时，通过旧 image 的 `GetTypeInfoFromTypeDefinitionRawIndex` 解析 `Il2CppClass*`，检查其 `image` 是否已被更新为 `newImage`
- `ShouldRestoreType` 中同样增加回退检查逻辑

### 第六次：根因定位 + 修复（已修复）
- **根因**：`AsyncUniTaskMethodBuilder`1` 的泛型定义来自 AOT（`gclass->type->data.typeHandle` 指向 AOT typeDef，`isInterpType=0`）
- 但泛型参数 `T` 来自重载 DLL → `ShouldRestoreGenericClass` 因泛型参数检查返回 true
- `RestoreCachedGenericClasses` 把 `klass->image` 改成 interpreter image（newImage）
- 但 `methodInfo->token` 仍是 AOT token（泛型定义的方法来自 AOT）
- `GetUnderlyingInterpreterImage` 因 `klass->image` 是 interpreter image 返回 interpreter image
- `GetMethodBody(AOT_token)` 在 interpreter image 上越界
- **修复**：`RestoreCachedGenericClasses` 中只有当泛型定义来自 interpreter image 时才更新 `klass->image = newImage`。AOT 泛型定义的实例类保持 `klass->image` 不变（仍为 AOT image），只重置 `initialized`/`methods` 等字段让 `Class::Init` 重新初始化

### 第七次：InvalidCastException（EnumEqualityComparer → EqualityComparer）
- `EqualityComparer`1[T].CreateComparer()` 返回 `EnumEqualityComparer`1`，但 cast 到 `EqualityComparer`1` 失败
- **根因**：`RestoreCachedGenericClasses` 在 `RestoreReusedClasses` Pass 3 之后才运行。非泛型 Pass 3 的 `Class::Init` cctor 可能访问泛型实例类，但此时泛型实例类的 type hierarchy 是旧的（parent/typeHierarchy 未重置），导致 cast 失败
- **修复**：将 `RestoreCachedGenericClasses` 拆成 3 个 Pass，与非泛型 Pass 交错执行：
  1. 非泛型 Pass 1（更新指针）→ 泛型 Pass 1（更新 image）
  2. 非泛型 Pass 2（重置字段）→ 泛型 Pass 2（重置字段）
  3. 非泛型 Pass 3（Class::Init）→ 泛型 Pass 3（Class::Init）
- 这样非泛型 cctor 访问泛型实例类时，泛型实例类已被重置，`Class::Init` 会正确重建 type hierarchy

### 第八次：IsInstClass 崩溃（typeHierarchyDepth 未重置）
- **崩溃位置**：`Unity.ResourceManager__1.cpp:3219`，AOT 代码 `IsInstClass`
- **根因**：非泛型 Pass 2 重置了 `typeHierarchy = nullptr` 但**没有重置 `typeHierarchyDepth`**。`IsInstClass` 检查 `typeHierarchyDepth > 0` 后访问 `typeHierarchy[0]`（NULL）→ 崩溃
- **修复**：在非泛型 Pass 2 中增加 `klass->typeHierarchyDepth = 0`
- **注意**：不要重置 `klass->parent`！`InitLocked` 不重建 parent，parent 是在类创建时从 TypeDef 的 parentIndex 设置的

### 第九次：FpsInfo not derived from MonoBehaviour
- **根因**：Pass 2 重置了 `parent = nullptr`，但 `InitLocked` 不重建 parent
- **修复**：从 Pass 2 中移除 `parent = nullptr`
- **增强**：非泛型和泛型的 parent 重新解析都移到 Pass 3（`Class::Init` 之前）
- Pass 1 不做 parent 解析，因为复用列表还没建完，`Class::FromIl2CppType`/`InflateIfNeeded` 可能触发类创建拿到意外对象
- reload 期间持有 `g_MetadataLock`，没有并发 Unity 原生代码，所以不需要在 Pass 1 提前设置 parent

### 第十次：AOT generic method not instantiated（ProxyPropertyInfo`2.ctor）
- **异常**：`MissingMethodException: AOT generic method not instantiated in aot. ProxyPropertyInfo`2[Transform,Vector3]::.ctor`
- **分析**：`TransformContext::TransformBodyImpl` 遇到 `newobj` → `IsInterpreterImplement(shareMethod)` 返回 false → `InitAndGetInterpreterDirectlyCallMethodPointer` 返回 nullptr → 异常
- **可能根因**：泛型类型定义的 `.ctor` 在 `SetupMethodsLocked` 中被复用时，`isInterpterImpl` 被设为 false（因为 `IsImplementsByInterpreter` 检查 `invoker_method`，如果 `methodPointer` 为 nullptr 则 `invoker_method` 是 `GetMissingMethodInvoker()`）
- **诊断日志**：在 `SetupMethodsLocked` 中，当 `.ctor` 的 `isInterpterImpl` 为 false 时打印 `methodPointer`、`virtualMethodPointer`、`invoker_method`、`token`
