## 问题：长时间运行再重启后 IsAssignableFrom 崩溃

### 崩溃栈
```
Class::IsAssignableFrom (Class.cpp:780)
StackTrace_GetFullNameForStackTrace
StackTrace_AddFrames
StackTrace_ToString
Exception_ToString
```

### 根因
`IsAssignableFrom` 的 `else` 分支遍历 `oklass` 的 parent 链，访问 `iter->implementedInterfaces[i]`，但没有检查 `implementedInterfaces` 是否为 NULL。

泛型实例类 `ProgressResult<T>` 在 reload 后：
- Pass 2 置空了 `implementedInterfaces`
- 泛型 Pass 3 调用了 `Class::Init`，但 `InitLocked` 可能在 `SetupInterfacesLocked` 之前抛出异常（通过 `longjmp`），导致 `implementedInterfaces` 保持 NULL
- 后续 `Class::Init` 调用时 `init_pending=1`，`InitLocked` 直接返回 true，但 `implementedInterfaces` 仍为 NULL

### 修复
在 `IsAssignableFrom` 的两个分支（`klass->generic_class != NULL` 和 `else`）中，对 `implementedInterfaces` 和 `interfaceOffsets` 添加 NULL 检查：
```cpp
if (iter->implementedInterfaces != NULL)
{
    for (uint16_t i = 0; i < iter->interfaces_count; ++i)
    {
        if (iter->implementedInterfaces[i] == klass)
            return true;
    }
}
```

### 关键代码位置
- `vm/Class.cpp` line 753-772: `klass->generic_class != NULL` 分支
- `vm/Class.cpp` line 774-790: `else` 分支
- `vm/Class.cpp` line 1703: `SetupInterfacesLocked` 在 `InitLocked` 中的位置
- `vm/Class.cpp` line 1719-1723: `InitLocked` 中 `initializationExceptionGCHandle` 检查（重置 `init_pending`）
- `vm/Class.cpp` line 1793-1797: `SetClassInitializationError` 调用 `PublishInitialized`（设置 `initialized=true`、`init_pending=false`）

## 问题：BackpackTabType ArgumentException — Il2CppTypeEqualityComparer 比较旧/新 typeHandle

### 根因
`Il2CppTypeCompare.cpp` 中 `Compare(Il2CppType*, Il2CppType*)` 对 CLASS/VALUETYPE 直接比较 `data.typeHandle` 指针值。reload 后，两个 `Il2CppType*` 可能分别持有旧 `typeDef` 和新 `typeDef` 指针，`AreEqual` 返回 false，即使它们解析到同一个 `Il2CppClass*`。

`ValidateOneArgument` → `Type.IsAssignableFrom` → `Il2CppTypeEqualityComparer::AreEqual` 比较 `Il2CppType*`，旧 `typeHandle` ≠ 新 `typeHandle` → 返回 false → 抛出 `ArgumentException`。

### 修复
在 `Il2CppTypeEqualityComparer::AreEqual` 中添加回退比较：当 `Compare` 返回非零且类型为 CLASS/VALUETYPE 时，通过 `GlobalMetadata::GetTypeInfoFromHandle` 解析两个 `typeHandle` 为 `Il2CppClass*`，比较指针。正常情况下（`typeHandle` 相同）无额外开销。

### 修改的文件
- `metadata/Il2CppTypeCompare.cpp` — `AreEqual` 添加 `typeHandle` 回退比较，增加 `#include "vm/GlobalMetadata.h"`
- `vm/Reflection.cpp` — `GetTypeObject` 中归一化旧 `Il2CppType*` 为 `&klass->byval_arg`，增加 `#include "vm/GlobalMetadata.h"`
- `vm/Class.cpp` — 清理 `SAME_NAME_DIFF_PTR` 诊断日志
- `vm/GlobalMetadata.cpp` — 清理 `BackpackTabType` 诊断日志，移除 `os/Directory.h`、`os/Environment.h`

### 根因详细分析
- `s_TypeMap`（`AppendOnlyGCHashMap`）用 `Il2CppType*` 指针作为 key，hash/compare 基于 `data.typeHandle`
- reload 后旧 `Il2CppType*`（`typeHandle`→旧 `typeDef`）仍在 `s_TypeMap` 中，新 `Il2CppType*`（`typeHandle`→新 `typeDef`）hash 不同 → 创建新 `Type` 对象
- C# `Type` 对象的 `type` 字段持有旧或新 `Il2CppType*`，`ValidateOneArgument` 比较时 `AreEqual` 返回 false
- `GetTypeObject` 归一化后，所有通过 `GetTypeObject` 获取的 `Type` 对象都使用新 `Il2CppType*`，避免 `s_TypeMap` 中产生重复条目
- `AreEqual` 回退比较作为安全网，处理不经过 `GetTypeObject` 的直接比较路径
