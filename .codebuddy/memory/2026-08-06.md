# 2026-08-06 工作日志

## Expression1<T> → Expression<T> InvalidCastException 修复

### 问题
reload 后 `HomeWindow.BindAll()` 中通过 `Expression.Lambda<TDelegate>` 创建表达式树时抛出：
```
System.InvalidCastException: Unable to cast object of type 'Expression1`1' to type 'Expression`1'.
```
`Expression1<T>` 是 `Expression<T>` 的子类（AOT 类型，在 System.Linq.Expressions 中）。cast 应该成功但失败了。

### 根因
`Il2CppGenericClassHash::Hash` 同时依赖 `gclass->type` 和 `gclass->context.class_inst->type_argv[i]`（通过 `Il2CppGenericContextHash` → `Il2CppGenericInstHash` → `Il2CppTypeHash`）。

rehash 函数 `RehashGenericClassSet` 和 `RehashGenericTypeSet` 更新了 `gclass->type` → `&klass->byval_arg`，但**未更新** `gclass->context.class_inst->type_argv`。

执行顺序：
1. Pass 1: 更新 `klass->byval_arg.data.typeHandle`
2. Rehash: 用陈旧 `type_argv` 重算 hash（`type_argv` 还没归一化）
3. Pass 2: 归一化 `type_argv` → `&newKlass->byval_arg`（但不 rehash）
4. Pass 3: lookup 用新 `type_argv` → hash 不匹配 → 创建重复条目

结果：`Expression1<T>->parent` 指向旧 `Expression<T>` 实例，但 cast 目标是新 `Expression<T>` 实例 → `HasParentUnsafe` 失败。

AOT 创建的 `class_inst` 不在 `s_GenericInstSet` 中，所以 `RehashGenericInstSet` 不会更新它的 `type_argv`。

### 修复
在 `RehashGenericClassSet`（GenericMetadata.cpp）和 `RehashGenericTypeSet`（GenericClass.cpp）中增加 `NormalizeGenericInstTypeArgv` 调用，在 rehash 时同时归一化 `gclass->context.class_inst->type_argv`，确保 hash 用归一化后的值计算。

### 文件改动
- `metadata/GenericMetadata.cpp`: 新增 `NormalizeGenericInstTypeArgv` static 函数，在 `RehashGenericClassSet` 中调用
- `vm/GenericClass.cpp`: 新增 `NormalizeGenericInstTypeArgv` static 函数，在 `RehashGenericTypeSet` 中调用

## "method arguments are incompatible" 修复（Delegate.CreateDelegate）

### 问题
`Delegate.CreateDelegate(Action<BackpackTabType, BackpackSubTabType>, vm, method)` 抛出 "method arguments are incompatible"。

### 根因
`ShouldRestoreType` 在 Pass 1 之前被调用（在 `RestoreCachedGenericClasses` 中遍历 `s_GenericClassSet` 时）。此时 `byval_arg.data.typeHandle` 还没被更新，和 `type->data.typeHandle` 匹配（`sameHandle=1`）→ 返回 FALSE → `Action`2<BackpackTabType, BackpackSubTabType>` 不在 `s_GenericClassesToRestore` → Pass 2/3 不重新 `SetupMethods` → `Invoke` 方法的 `parameters` 数组保持陈旧（inflate 自旧 `type_argv`，`typeHandle` 指向旧类型表）→ Pass 1 后 `byval_arg.data.typeHandle` 更新 → 旧 `typeHandle` 失效 → `Class::FromIl2CppType` 对旧 `typeHandle` 返回 NULL → `IsAssignableFrom` 返回 FALSE → "method arguments are incompatible"

### 关键
- `IsEqualToType FAIL` 日志未触发 → 比较走 `Class::IsAssignableFrom` 而非 `Type::IsEqualToType`
- `ShouldRestoreType FAIL` 全部 `sameHandle=1` → 因为 Pass 1 还没运行
- `Action FALSE` 条目中有些 `type_argv` 全是热更 DLL 类型，但 `ShouldRestoreType` 返回 FALSE

### 修复
`ShouldRestoreType` 增加新检查：如果类型是解释器类型，且 `&resolvedKlass->byval_arg != type`（`Il2CppType*` 来自旧类型表，不是 `&klass->byval_arg`），返回 TRUE。即使 `typeHandle` 当前匹配，Pass 1 后也会变，导致 `Invoke` 方法的 `parameters` 失效。

## "method arguments are incompatible" 最终修复（rehash 后重置 methods）

### 问题
`AreEqual FAIL` 日志确认比较走 `AreEqual` 路径，50 条 CLASS/VALUETYPE 类型比较失败，`typeHandle` 不匹配。

根因：`Action`2` 的 `Invoke` 方法的 `parameters` 是在创建时从 `type_argv` inflate 出来的。rehash 归一化了 `type_argv[i]` → `&klass->byval_arg`，但 `method->parameters[i]` 仍持有旧的 `Il2CppType*`（rehash 之前的值）。

`ShouldRestoreGenericClass` 在 Pass 1 中对 `samePtr=1, sameHandle=1` 的类返回 FALSE（因为 rehash 已经更新了 `type_argv`），所以它们不在 `s_GenericClassesToRestore` 中，Pass 2 不重置 `methods`，`parameters` 保持旧值。

### 修复
1. `RehashGenericInstSet`（MetadataCache.cpp）：记录哪些 `Il2CppGenericInst` 的 `type_argv` 发生了变化（`s_ChangedInsts`），暴露 `WasGenericInstChanged(inst)` 查询接口。
2. `RehashGenericClassSet`（GenericMetadata.cpp）和 `RehashGenericTypeSet`（GenericClass.cpp）：调用 `NormalizeGenericInstTypeArgv` 后，如果返回 `true` 或 `WasGenericInstChanged(gclass->context.class_inst)` 返回 `true`，将 `gclass->cached_class->methods` 置空，让下次 `SetupMethods` 重新 inflate `parameters`。

### 关键
- `RehashGenericInstSet` 先运行，更新 `s_GenericInstSet` 中的 `type_argv`
- `RehashGenericClassSet` 后运行，`NormalizeGenericInstTypeArgv` 发现 `type_argv` 已经是 `&klass->byval_arg`（`samePtr=1`），不会返回 `changed=true`
- 所以需要 `WasGenericInstChanged` 来检测 `RehashGenericInstSet` 是否更新了这个 `inst`

## "method arguments are incompatible" 最终修复（ClearTypeMapForReload）

### 问题
`Delegate.CreateDelegate` 比较参数类型用的是 `Type == Type` (引用相等)，不是 `Type.Equals` → `AreEqual`。所以 `IsEqualToType FAIL` 和 `AreEqual FAIL` 日志都不会触发。

### 根因
`Reflection::GetTypeObject` 使用 `s_TypeMap` 缓存 `Il2CppType*` → `Il2CppReflectionType*`。键是 `Il2CppType*` 指针。

reload 后，`method->parameters[i]` 可能持有旧的 `Il2CppType*`（指向旧类型表），而委托 `Invoke` 的 `parameters[i]` 持有 `&klass->byval_arg`（新的）。`GetTypeObject` 对两个不同的 `Il2CppType*` 返回不同的 `Il2CppReflectionType*` 实例。C# 的 `==` 比较返回 FALSE → "method arguments are incompatible"。

### 修复
在 `RestoreReusedClasses()` 中调用 `ClearTypeMapForReload()`，清空 `s_TypeMap`。这样 `GetTypeObject` 会用新的 `Il2CppType*` 重新创建 `Il2CppReflectionType*`，确保同一个类型只有一个 `Il2CppReflectionType*` 实例。

### 文件改动
- `vm/Reflection.cpp/.h`: 新增 `ClearTypeMapForReload()`
- `hybridclr/metadata/InterpreterImage.cpp`: 在 `RestoreReusedClasses()` 中调用 `ClearTypeMapForReload()`
